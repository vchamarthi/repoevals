## 1. Purpose, motivation, scope, review history

### Purpose (from the PR body and `README.md:17-27`)
- It is a benchmark for **coding agents** (Claude Code, Copilot, Codex) working on oneDAL. It does not test oneDAL itself.
- There are 27 fixed tasks across build, fix, feature, test-writing and review. Each one has a deterministic pass/fail or score grader.
- **Main goal: A/B-test the repo's agent guidance.** oneDAL has had `AGENTS.md` files and `.github/instructions/` since #3335, and PRs keep editing them (e.g. #3812). Until now nobody could tell whether an edit helps.
  - The same tasks run under *arms*: `guidance:none` (guidance files deleted) vs `guidance:raw` (as checked in), or old vs new guidance.
  - The same method can judge changes to the build system, tooling or repo layout.
- A free secondary product is the **T0 static claim check** (`run.py static`). It checks that every path, Bazel label, command and identifier named in the guidance exists in the tree.
  - On main 53781ebf2 it checked 349 claims and flagged 8. One was a real error: `//examples/oneapi/cpp:kmeans` does not exist.
- Three tiers (`README.md:41-45`):

  | tier | command | cost |
  |---|---|---|
  | T0 static | `run.py static` | $0, seconds |
  | self-check | `run.py check` | CPU only |
  | T1 agent runs | external agent-benchmark | LLM tokens + CPU |

### Scope split (commit `7d1da748`, 2026-10-04)
- Early versions shipped a full agent runner. It had:
  - a `claude -p` driver with `--permission-mode bypassPermissions`, per-model budget caps of $2/$5/$10, and WebFetch/WebSearch disallowed;
  - a `no_background.py` PreToolUse hook and a process-group kill;
  - `traces.py`, `summarize.py`, and a matrix of arms × models × reps.
- All of that moved to **agent-benchmark**, an Intel-internal runner that is "to be published". It reads `repo-eval.yaml`.
- The repo now keeps only the oneDAL-specific parts: tasks, graders/oracles, contract entry points, the static checker, the Docker image and the Bazel wrapper.

### Pilot results (PR body; `tasks/README.md:115-129`)
- First pilot: haiku with Claude Code 2.1.286, 25 tasks × 2 arms × 3 reps = 150 runs, about $56. Later status: 156 haiku runs and 48 opus runs.
- Pass/fail tasks: 29/51 without guidance vs 32/51 with it (p≈0.7). The PR concludes there is **no measurable guidance effect**.
- Replay recall: 0.18 vs 0.19. Seeded review recall: 0.33 vs 0.62. This is the clearest signal, but it rests on 3 runs.
- Too easy (6/6 in both arms): 7 tasks.
- Discriminating: `build_make_gnu`, `fix_df_bestfirst`, `fix_kmeans_empty_reloc`, `fix_table_csr_zero_based`, `feat_cosine_self`, and all review tasks.
- Never solved by haiku: `fix_cel_thread_race`, `fix_df_extratrees_reg`, `test_add_minkowski`.
- `fix_pca_online_signflip` and `fix_table_csr_accessor` have no guidance file at their base, so both arms are identical there. They are excluded from arm comparisons.

### Data flow

```
agent-benchmark (external)                               dev/agent_evals (this PR)
──────────────────────────                               ─────────────────────────
read repo-eval.yaml
workspace = git archive <base> (no history), minus dev/agent_evals
  + setup patches (committed as root commit)
  + arm (delete guidance.globs for guidance:none)
  + git am review_patch (review tasks → HEAD commit)
run agent in its own container (image from Dockerfile,
  network none, caches mounted, cwd=workspace)
normalize trace → events.jsonl, answer.txt, meta.json
                                                     ──► python3 {eval_dir}/run.py grade --contract {run_dir} --source {source_dir}
                                                         contract.grade(rd):
                                                           task.json, meta.json → start_commit()
                                                           metrics(rd) from events.jsonl
                                                           GRADERS[t.grader](rd, ws, t, trace)
                                                           → grade.json {schema: repo_grade.v1, task, grader,
                                                                         pass, metrics{}, details{}, errors[]}
                                                         bazel shutdown (finally)
repo report repo-runs/<batch>
```

- **How the agent under test is invoked:** not in this repo any more.
  - agent-benchmark command (`README.md:78-83`): `python cli.py repo run <oneDAL>@<sha> --manifest dev/agent_evals/repo-eval.yaml --arm guidance:none,guidance:raw --model <id> --reps 3 --batch b1`.
  - The agent sees only the task `prompt`. The output contract is a final fenced ```` ```json ```` block where the grader needs one (`common.last_json`, `common.py:114-121`: the last block that parses).
  - The pre-split invocation (removed) was `claude -p <prompt + "work in the foreground"> --model … --output-format stream-json --permission-mode bypassPermissions --max-budget-usd … --disallowedTools WebFetch WebSearch [--effort]`. It also had a PreToolUse hook that refused background shell commands, and required CLI ≥ 2.1.286 so `AGENTS.md` is auto-loaded.
- **Sandboxing and isolation:**
  - The snapshot has no history and no eval directory (`common.py:57-68`, `config.EVAL_DIR_IN_REPO`).
  - Agent and grader run in separate containers. `{eval_dir}` is a read-only framework copy. The full-history source clone is visible only to the grader: `run_env` pops `ONEDAL_EVAL_SRC` (`config.py:86`), and `show()` reads it in-process.
  - `image.network: none`.
  - Each run gets its own Bazel output base (`{run_dir}/ob`). The repository cache, disk cache, BCR mirror and install root are shared across runs.
  - Grader-written files are restored afterwards (`files_restored`).
  - Hosts the task cannot meaningfully run on raise `HostUnsupported`: the grade is recorded as not graded, and `check` reports SKIPPED.
- **What "no-LLM CI" means exactly** (`.github/workflows/agent-evals.yml`):
  - Triggers: pull requests to main touching `dev/agent_evals/**`, `**/AGENTS.md`, `.github/instructions/**`, `.github/copilot-instructions.md`, `CONTRIBUTING.md` or the workflow itself (`:24-33`); a weekly cron `0 3 * * 0` (`:34-35`); and `workflow_dispatch` with a task list (`:36-41`).
  - Job `validate` (ubuntu-24.04, 20 min, fetch-depth 0):
    - `run.py validate` as a **gate**.
    - `run.py static --out static.json` as **report only**: a markdown table in the job summary plus an artifact (`:63-86`).
    - Selects tasks for the self-check (`:87-112`):
      - pull requests: the tasks changed, plus a smoke set (one task per grader: `build_kmeans_host build_make_gnu build_release_host fix_finiteness_mut fix_avx2_dispatch review_seeded_fc review_replay_pr3580 test_add_chebyshev`) when any non-task, non-`.md` file under `dev/agent_evals` changes;
      - schedule: all tasks;
      - dispatch: the input list or all tasks.
      - Task names are sanitised with the regex `^[A-Za-z0-9_]+$`.
  - Job `self-check`, a matrix with max-parallel 4, fail-fast off, 180-minute timeout:
    - Builds the image from `git archive HEAD` minus `tasks/`.
    - Runs `docker run --init --user … -v $PWD:/harness:ro -v $PWD:/src:ro … run.py check <task>`.
    - Clones the BCR mirror if the cache is empty.
    - Uploads `grade.json` and logs on failure (`:114-159`).
  - No model, API key or token is involved. The self-check proves for every task that the **null** (untouched) workspace fails and the **oracle** (reference) passes (`run.py:91-109`).
  - It takes 17–35 minutes per task on GitHub runners.

### `run.py check` semantics (`run.py:74-109`)
- `check(task, kind)` does the following:
  - `prep()` builds the contract layout at `$ONEDAL_EVAL_ROOT/check/<task>__<kind>/`: `workspace/`, `task.json`, `meta.json` with `arm=guidance:raw`, `base_rev`, `base_sha`, `base_date`, `start_sha`, plus an empty `answer.txt` and an empty `events.jsonl`.
  - For `kind=oracle` it applies `ORACLES[grader]`.
  - It then calls `contract.grade` and shuts Bazel down.
- `check_verdict` decides the outcome:
  - If both null and oracle raise `HostUnsupported` → SKIPPED (OK).
  - Any grader error → GRADER BROKEN.
  - Review family:
    - with `score`: the oracle's `score.metric` must reach ≥ `score.max`, the oracle must flag no decoys, and the null answer must produce `parse_error`;
    - without `score` (clean control): the oracle must pass.
  - Every other family: null must have `pass is False` and oracle `pass is True`.

## 3. Task schema

### `task.json` core keys (`run.py:44` `CORE_KEYS`; `README.md:104-113`)
- **Required:** `id` (must equal the directory name), `family`, `base`, `prompt`, `grader`.
  - `family` is one of `build`, `feature`, `fix`, `review`, `test`. Note that `README.md:107` omits `feature`.
  - `base` is a full 40-character SHA, optionally with `^` for mined fixes (`run.py:55-59`).
- **Workspace keys:**
  - `setup_patch` / `setup_patches`: applied and amended into the root commit.
  - `review_patch`: applied with `git am` as HEAD, authored as "Dev Contributor".
- **Gating and scoring:**
  - `gate`: list of metric names. The default is `["pass"]`. All fix and feature tasks use `["strict_pass"]`. `validate` also accepts `{"metric","min"}` dicts (`run.py:65-67`).
  - `score`: `{"metric":"recall","max":1.0}` on score-only review tasks.
- **Provenance only (never read by graders):** `source_pr`, `source_issue`, `reviewed_commit`.
- **Grader-specific keys:**
  - `test_pass`: `hidden_from`, `hidden_files`, `targets`, `regression_targets`, `root_cause{file,must_contain}`, `oracle_patch`.
  - `test_pass_files` adds: `test_flags`, `regression_flags`, `root_cause{must_contain|must_not_contain}`, `min_cpus`, `cpu_vendors`, `cpu_flags`; plus a `hidden/` tree in which BUILD files are stored as `BUILD.oracle`.
  - `bazel_cmd`: `expect_target`.
  - `release_path`, `artifact_path`, `make_artifact`: `artifact_re`, `path_must_contain`.
  - `mutation`: `package`, `mutants`, `min_kill`, `oracle_targets`, plus an `oracle/` tree.
  - `review`: `manifest`, `oracle_answer`.
  - `review_replay`: `gold`, `window`.

### Family-by-family

**build — `bazel_cmd`** (`graders/build.py:25-38`)
- Agent's job: build and test K-Means with Bazel, then report the command as `{"command": …}`.
- Grading:
  - The command must match `^bazel\s+test\b` and contain no `;&|`$<>\r\n`, and `shlex` must parse it.
  - The grader reruns it through `bin/bazel` with `--nocache_test_results` appended.
  - pass = rc 0 **and** the regex `<expect_target>\s+PASSED` appears in the log.
- Oracle: `bazel test <expect_target>`.

**build — `release_path`** (`graders/build.py:41-52`)
- Agent's job: build the CPU release package and report the path of `libonedal_core`.
- pass requires all of:
  - the path resolves inside the run dir (`resolve_in_run`, symlink-aware, rebases `/eval/run`);
  - it is a regular file whose name matches `artifact_re` (default `libonedal_core\.so`);
  - the raw path contains `path_must_contain` (default `release`);
  - the first 4 bytes are `\x7fELF`.
- Oracle: `bazel build //:release --release_dpc=false`, then glob `bazel-bin/release`.

**build — `make_artifact`** (`graders/make.py:30-56`)
- Grading is `g_artifact_path`, plus no `bazel|bazelisk build|test|run` may appear in `events.jsonl` commands.
- `path_must_contain: "__release_lnx"`.
- Oracle: `make -f makefile daal PLAT=lnx32e COMPILER=gnu REQCPU=avx2 -jN` with `MKLROOT=TBBROOT=/opt/onedal-make-deps`.

**fix / feature — `test_pass`** (`graders/fix.py:23-57`)
- The agent fixes the bug or implements the feature from a bug-report or feature-request prompt.
- Grading steps:
  1. `changed_files` vs `start_sha` (tracked diff plus untracked files). These are split into `touched_tests` (matched by `/test/` or `_test.cpp`) and `src_changed`.
  2. Inside `files_restored(hidden_files)`, write each hidden file from `git show hidden_from:<path>` out of the full-history clone, overwriting whatever the agent did to it.
  3. `bazel test <targets> --test_output=errors --nocache_test_results` → `pass = rc==0`.
  4. Same for `regression_targets` → `regress_pass`; `strict_pass = pass and regress_pass`.
  5. Hygiene: `format_ok` (clang-format 20.1.8 `--dry-run -Werror` on changed C/C++ files), `diff_lines` (non-test diff), and `root_cause_fixed` (exact substring `must_contain` in a file).
- Reference: the oracle (`:60-73`) applies, in order of preference:
  - `oracle_patch`, else
  - the setup patches reversed, else
  - the mined fix commit's non-hidden files copied from `base.rstrip("^")`.
- The task passes on `strict_pass` (the gate).

**fix — `test_pass_files`** (`graders/fix_hidden.py:40-75`)
- Runs `require_host(t)` first.
- Hidden files are taken from `tasks/<id>/hidden/<path>`, falling back to `<path>.oracle`, then to `show(hidden_from, path)`.
- Adds `test_flags` and `regression_flags`, then delegates to `g_test_pass` with the pre-write `_changed_files`.
- `root_cause` supports `must_contain` and/or `must_not_contain`; a missing file counts as not fixed.

**test — `mutation`** (`graders/mutation.py:78-142`)
- Agent's job: add CPU tests for Chebyshev or Minkowski distance as used by brute-force kNN, then report `{"targets":[…]}`.
- Validation:
  - Targets must be `//<package>:<name>` inside `package`.
  - At least one authored test or BUILD file must exist in the package.
- Grading:
  - Library sources the agent modified or added (anything that is neither a test nor a BUILD/`.bzl` file) are reverted to base or deleted for the duration of grading, then restored.
  - Baseline: targets must pass (`rc==0` and `Executed N>0`).
  - Each mutant patch is applied in turn, targets are run, and the patch is reverted. `killed = rc==3`. Any rc other than 0 or 3 is a `build_error` and is excluded from the denominator. A patch that fails to apply is `apply_error`.
  - `kill_rate = killed / live`; `pass = kill_rate ≥ min_kill` (0.6, so 5 of 7 mutants).
  - Reported: `n_tests` (TEST/TEST_M/TEMPLATE_*TEST* macro count), `diff_lines` (`authored_lines` includes new files), `format_ok`, `survived`, and per-mutant rc.
- Oracle: copies `oracle/` (stripping `.oracle`) and answers `oracle_targets`.
- Chebyshev mutants:
  - c1: drop `sFabs`
  - c2: sum instead of max
  - c3/c4: skip the last/first feature
  - c5: `float` accumulator
  - c6: swapped result index
  - c7: dispatch to Euclidean in `bf_knn_impl.i`
- Minkowski mutants:
  - m1: degree ignored (`2.0` hard-coded in `knn/detail/distance.cpp`)
  - m2: `<=` → `<` lets `p=0` through
  - m3/m4: no abs
  - m5: `vPowx(…, 0.5)` instead of `1/p`
  - m6: dispatch to Euclidean for p≥2
  - m7: skip the last feature

**review — seeded, decoys, clean control (`review`)** (`graders/review.py:58-94`)
- The agent reviews `git show HEAD` and returns findings `[{file,line,severity,rule,message}]`.
- Manifest format: `seeds [{id,class,file,lines,kw}]` and `decoys [{id,file,lines,kw,evidence?}]`.
- Matching, per finding:
  - Normalise the path (`norm_path` strips `./`, `\`, and the prefix up to `/repo/`).
  - Seed hit if the file matches (or the seed's file is `*`) **and** the regex `kw` matches the rule, message or evidence text (case-insensitive).
  - Otherwise, the nearest seed within ±1 line of `lines` (only one seed credited).
  - Otherwise, if a decoy matches on file plus (kw or exact line), it is a false positive.
  - Otherwise it counts as `unmatched`.
- Outputs: `recall = |hit|/|seeds|`, `recall_by_class` (classes: guideline, maintainer, generic), `decoys_flagged`, `n_decoys`, `unmatched`, `n_findings`, `n_severe` (blocker or major).
- `pass=None` (score-only) except for the clean control (no seeds), where `pass = n_severe==0`.
- `parse_error` is raised when no JSON list is found.
- `review_seeded_fc`: seeds S1 header guard, S2 licence, S3 raw `new[]`, S4 throw in DAAL, S5 `std::span` (C++20; `file:"*"`), S6 copyright-year-only edit, S7 `cout`, S8 off-by-one `<= n`. Decoys D2–D7 are idiomatic DAAL/oneAPI code.
- `review_guidance_decoys`:
  - Seeds: last-block `nRows % blockSize` bug, `std::mutex` instead of the threading layer, `#pragma once` in DAAL, a literal error message, the wrong `result_option`, and a new-file copyright style.
  - The 6 decoys break the *literal* guidance text but are normal DAAL practice, and each carries a quantitative `evidence` string. Examples: `PRAGMA_OMP_SIMD` is used 275 times in `cpp/daal`; `_member` prefixes appear 865 times; `TArray` 525 times; `daal::tls<T*>` with raw `new` is the norm; and every oneAPI CPU backend mixes in DAAL calls.
  - The point is to detect guidance that is too literal.
- `review_clean_control`: PR #3775 merged clean. `oracle.json = []`; the agent passes if it reports no blocker or major finding.

**review — replay (`review_replay`)** (`graders/replay.py:45-76`)
- Gold format: `gold.json [{id,file,line,kind,comment,addressed,comment_id[,start_line]}]`.
  - `kind` is one of correctness, api, tests, convention, docs, nit.
  - `addressed` records whether the code changed before merge.
- Matching: a finding near a gold thread is one in the same file with `|line − gold.line| ≤ window` (5). Pairs are assigned one-to-one, nearest first.
- Outputs:
  - `recall_all = recall`, `recall_addressed`, `recall_by_kind`;
  - `precision_proxy` = findings near any thread ÷ n_findings (a lower bound);
  - `n_severe`, `threads_hit`, and an empty `decoys_flagged`.
- `pass=None` always.
- Oracle: one finding per gold thread at its anchor.
- The gold data holds verbatim human comments. Reviewer names and @-mentions were removed; `comment_id` was kept.

## 5. Standards, conventions and design principles
- **Contamination and leak control:**
  - History-free `git archive` snapshot with `dev/agent_evals` deleted (`common.py:57-68`).
  - Hidden tests are written only during grading and then restored.
  - The full-history clone is visible only to graders (`config.py:86` pops `ONEDAL_EVAL_SRC` from the build environment).
  - The image never copies `tasks/`, and is built from the archive minus `tasks/` (`Dockerfile:17-24`).
  - `network: none`.
  - Review patches are re-authored as "Dev Contributor <dev@example.com>".
  - **Missing:** no canary strings, no held-out private split, no time-based split implemented. Training-data contamination is acknowledged only.
- **Hidden tests and oracles:**
  - Mined tasks use the upstream PR's own test, applied at `fix^`.
  - Constructed tasks use hand-written hidden tests (`hidden/`), or the original tests when a feature has been removed.
  - `BUILD.oracle` keeps the eval tree free of Bazel packages.
- **Self-check invariant:** null fails and oracle passes, enforced in CI per changed task and weekly for all. "A task that cannot show both is broken."
- **Strictness:** `strict_pass` means hidden tests **and** the component's regression suites pass. `root_cause_fixed` catches symptom patches; it is recorded, not gated.
- **Decoys and controls:**
  - Decoys measure guidance that is too literal: the guidance text says X, but codebase practice is Y, with counted evidence.
  - The clean-diff control measures false-alarm rate.
  - Replays measure the real distribution of human review comments.
- **Determinism:**
  - `--nocache_test_results` on every test run.
  - Graders undo their writes, so regrades give byte-identical `grade.json` (verified on `fix_cel_thread_race`).
  - Matching is sorted and one-to-one.
  - `static_check` walks the tree in sorted order.
  - The race task uses `--runs_per_test=10` plus a hardware gate instead of pretending to be deterministic.
- **Hermetic toolchain:** image pinned by digest, bazelisk pinned by sha256, Bazel versions pre-fetched, a BCR mirror (task bases have no `MODULE.bazel.lock`), clang-format pinned to CI's 20.1.8, and MKL/TBB pins.
- **Security hygiene:**
  - No shell anywhere: argv only, and `shlex` for agent commands.
  - Agent-reported paths are confined to the run dir.
  - The CI workflow uses `permissions: contents: read`, SHA-pinned actions, a task-name regex, and passes the task as `$0` rather than interpolating it.
- **Licensing:**
  - Python, README, Dockerfile, YAML and hidden `.cpp` files carry the Apache-2.0 "Copyright contributors to the oneDAL project" header.
  - `.github/.licenserc.yaml` exempts `dev/agent_evals/tasks/**/*.json`, `**/*.patch` and `**/BUILD.oracle`, because those formats cannot carry a header.
  - Some `.py` files use "Copyright Contributors to the oneDAL Project" (capitalised) and others lower case; cosmetic only.
- **CODEOWNERS:** `dev/agent_evals/ @napetrov @homksei @ahuber21 @ethanglaser`, with a comment line above it (open review: drop the comment and @ahuber21).
- **Isolation of contributor impact:** no oneDAL build includes this directory. Other workflows already ignore `dev/agent_evals/**`.

## 7. Weaknesses, gaps, improvement ideas

### Grading validity and gameability
- **Review scores are recall-only, with no precision penalty.**
  - Replay: one finding on every line of every changed file gives recall 1.0, because matching is location-only within ±5 lines (`replay.py:52-62`). `precision_proxy` and `n_findings` are reported but do not affect the score.
  - Seeded: a keyword hit needs only the same file, with no line proximity (`review.py:68`). One finding with a keyword-stuffed message can credit **several** seeds; the one-to-one fix applied only to the line fallback. `S5_span` uses `file:"*"`, so a single "C++20/std::span" mention anywhere hits it.
  - **Fix:** score F1 or recall − λ·FP; cap the number of findings; require line proximity **and** keyword; assign keyword hits one-to-one.
- **Clean control is severity-only** (`review.py:92-93`): an agent passes by labelling everything "minor". Count all findings, or the share of severe ones.
- **Build tasks don't check that the tree is untouched**, even though prompts say "Do not modify any files". `bazel_cmd` reruns in the agent-modified workspace, so an agent could edit the K-Means test or BUILD and still pass.
- **`release_path` / `make_artifact` accept any ELF file named `libonedal_core.so*`** under a path containing `release`/`__release_lnx` inside the run directory (`build.py:50-51`). Copying `/bin/true` there would pass. There is no provenance check (Bazel output tree, SONAME, exported DAAL symbols).
- **The make task's Bazel ban relies only on the trace** (`make.py:33`). It passes if `events.jsonl` is missing or Bazel is called through a script. It also cannot tell a Bazel-built library copied into `__release_lnx_gnu` apart from a make-built one.
- **Regression test files are not restored to pristine.** "Do not weaken or delete existing tests" is enforced only by reporting `touched_tests`. An agent can weaken a regression-suite test and still get `strict_pass`. Fix: restore every test file under the regression packages from `start_sha`, or fail when one is touched.
- **Hidden BUILD files overwrite whole package files.** `fix_cel_thread_race` replaces `cpp/daal/BUILD` (401 lines), so an agent's legitimate BUILD change is dropped during grading.
- **`fix.py:54-56` crashes when the `root_cause` file is missing** (`read_text` raises), so the whole grade becomes `pass=None` / "not graded" instead of fail. This affects `fix_finiteness_mut` and `feat_xparam_cov_bias`. `fix_hidden.py:66-74` handles the case correctly.
- **`root_cause` is exact-substring matching.** `fix_finiteness_mut` requires the original line verbatim, so it is brittle against equivalent fixes. It is not gated.
- **Mutation self-check does not enforce what the docstring promises.** `mutation.py:23-24` says each mutant must be killed by the reference tests, but `check_verdict` only needs the oracle's `kill_rate ≥ 0.6`.
  - Mutants that fail to build are dropped from the denominator, so a build-breaking mutant set silently shrinks the denominator.
  - `c5_float_accumulator` is close to an equivalent mutant on float inputs.
- **Mutation grading leaves agent edits to BUILD/.bzl files outside the package and to `/test/` infrastructure anywhere** (e.g. `cpp/oneapi/dal/test/engine/`). Those edits stay active for both the baseline and the mutant runs.
- **The review null check is weak.** It only requires `parse_error` on an empty answer (`run.py:105`). There are no adversarial probes (spam findings, fake artifact, deleted tests) proving each grader rejects gaming. **Idea:** add per-grader "adversarial oracles" to `check`.

### Isolation, determinism, cost
- **Bazel state is shared across agent, grader and runs.**
  - The grader reuses the agent's output base `{run_dir}/ob`, including `external/`.
  - The disk and repository caches are writable by every agent container (`chmod 1777`, `Dockerfile:76-77`).
  - So a run could poison compile outputs for later runs or for its own grading.
  - **Fix:** grade with a fresh output base, and mount the caches read-only for agents (or keep them per run).
- **`fix_cel_thread_race` is probabilistic.** It runs 10 times, needs 4 or more GenuineIntel CPUs, and is mostly SKIPPED on GitHub's AMD runners. A partial fix can pass flakily, and CI cannot validate the task.
- **The `fix_avx2_dispatch` prompt claims "The machine you are working on is an AVX-512 server"**, which is false on AMD EPYC (AVX2-only) hosts. There, existing tests may fail and give the bug away.
- **CI cost:**
  - 17–35 minutes per task.
  - The Docker image is rebuilt in every matrix job, and Bazel caches start cold per job (no `actions/cache`); the BCR mirror is cloned per job.
  - The weekly run is 27 jobs.
  - Mutants in `service_kernel_math.h` trigger large DAAL rebuilds, ×7 per test task.
- **Process metrics are coarse:**
  - `tool_calls` counts all events (`metrics.py:52`).
  - `BUILD_FAILED` matches any `\bFAILED\b` or `Error \d+`.
  - `guidance_read` counts `CLAUDE.md`, which no arm touches.
- **`diff_lines` misses new files** (`common.py:288-292`). The author found this in his own review sweep and it is still open; `mutation.authored_lines` already does it right.

### Task design and contamination
- **`fix_df_bestfirst` leaks the fix.**
  - The prompt (`tasks/fix_df_bestfirst/task.json:16`) is the issue text *after* it was updated. ### Improvement ideas
1. Add a precision-aware review score (F1 or FP-penalised), one-to-one keyword matching with line proximity, a cap on findings, and per-thread keyword sets for replay gold (still no LLM).
2. Add adversarial self-check probes per grader: findings spam, fake ELF, deleted tests, edited regression tests, a symptom-only fix.
3. Isolation: run the grade in a fresh output base, keep agent caches read-only or per-run, and check `git status` cleanliness for build tasks.
4. Statistics:
   - pass@k / pass^k, bootstrap CIs, paired per-task McNemar or permutation tests between arms;
   - minimum detectable effect planning, given the ~3 → 8+ reps guidance;
   - mixed-effects models across task, rep and model.
5. Contamination: canary strings in task files, reporting split by base date vs model cutoff, a private rotating holdout of mined tasks, and paraphrased prompts.
6. Schema: JSON Schema for `task.json`, gold and manifest files, enforced by `validate`; implement or forbid `{"metric","min"}` gates.
7. Generic core: extract the build/test adapter and repo-policy config so the graders run on sklearnex, SVS and others. This matches ethanglaser's concern and the agent-benchmark direction.
8. Cost/time: put tokens, cost, wall time and turns into `grade.json` from `meta.json`, so efficiency can be compared across arms.
9. New families: review+fix (the reviewer's suggestion), GPU/SYCL behind host gating, doc/example tasks, and "update AGENTS.md after a refactor" tasks.
10. CI: cache the image and Bazel caches between jobs, add a nightly lane on an Intel runner so `fix_cel_thread_race` actually gets checked.
